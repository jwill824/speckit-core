# AI Tool Integrations

`speckit-core` is AI-tool-agnostic. It ships integration adapters for known tools under `.specify/integrations/<tool>/`, and uses a generic linker to wire an AI kit into a consumer project at bootstrap time.

## How it works

```
speckit-core         →  workflow engine + integration adapter scripts
<tool>-kit           →  AI-tool-specific assets (agents, prompts, commands)
consumer repo        →  receives linked assets from both via install.sh
```

The linker (`link-ai-integration.sh`) reads a manifest from the AI kit repo and creates the appropriate symlinks in the consumer project. It is AI-tool-agnostic — any kit that ships an `ai-kit.manifest.json` works with the same linker.

## Integration adapter scripts

`specify init` places integration scripts under `.specify/integrations/<tool>/scripts/` in the consumer project. These are lifecycle hooks speckit calls to coordinate with the AI tool (e.g., updating context windows). They are source content owned by `speckit-core`.

Installation records (`integrations/<tool>.manifest.json`) are **not** committed — they are project-local state and are gitignored.

## `ai-kit.manifest.json` — the kit contract

Each AI kit repo must ship a `.specify/ai-kit.manifest.json` that declares:

- What paths the kit owns
- How they should be linked into consumer projects (`link_dir`, `link_children`, or `copy`)
- Any conditional linking rules (e.g., skip `speckit.*` agents when `.speckit` is not present)

This file is **hand-maintained** by the kit author — think of it like `package.json` for the kit's linking contract. It is committed to the kit repo as source and is not generated by `specify init`.

### Example manifest (copilot-kit)

```json
{
  "schema_version": "1.0",
  "integration": "copilot",
  "version": "1.0.0",
  "links": [
    {
      "source": ".github/agents",
      "target": ".github/agents",
      "mode": "link_children",
      "skip_patterns_unless_paths_exist": [
        { "patterns": ["speckit.*"], "paths": [".speckit"] }
      ]
    },
    { "source": ".github/prompts", "target": ".github/prompts", "mode": "link_dir" },
    { "source": ".github/skills",  "target": ".github/skills",  "mode": "link_dir" },
    { "source": ".github/hooks",   "target": ".github/hooks",   "mode": "link_dir" }
  ],
  "copies": [
    {
      "source": ".github/copilot-instructions.md",
      "target": ".github/copilot-instructions.md",
      "if_missing": true
    }
  ]
}
```

### Manifest authoring guidelines

| Field | Notes |
|-------|-------|
| `mode: link_dir` | Symlinks the entire directory. Use for directories that are fully kit-owned. |
| `mode: link_children` | Symlinks each file individually. Use for directories where project-local files may co-exist (e.g., `.github/agents`). |
| `mode: copy` + `if_missing` | One-time copy of a seed file. Use for files the project customizes after init (e.g., `copilot-instructions.md`). |
| `skip_patterns_unless_paths_exist` | Conditional linking. Skip files matching `patterns` unless all `paths` exist in the consumer repo. Use this to gate speckit-specific agents behind `.speckit` presence. |

Update the manifest any time you add a new owned directory or change a linking strategy.

## Adding a new AI kit

To create a `claude-kit` (or any future kit):

1. Create `<tool>-kit/.specify/ai-kit.manifest.json` declaring owned paths (e.g., `.claude/commands`).
2. The generic linker requires no changes — it reads the manifest at runtime.
3. In the consumer repo, set `ai_tool: "claude"` in `.specify/project-tooling.json`.
4. The bootstrap workflow calls the linker with the kit path; everything wires up automatically.

## `project-tooling.json` — the consumer's selection

Consumer repos declare their AI tool and speckit preference in `.specify/project-tooling.json`:

```json
{
  "spec_workflow": true,
  "ai_tool": "copilot",
  "ai_kit_path": ".copilot-kit"
}
```

The linker reads this at runtime. Setting `spec_workflow: false` causes the linker to skip all `speckit.*` assets even if the kit ships them.

## What lives where

| Content | Owner | Committed to |
|---------|-------|--------------|
| Workflow engine, extension hooks | `speckit-core` | `speckit-core` |
| Integration adapter scripts | `speckit-core` | `speckit-core` (.specify/integrations/\<tool>/scripts/) |
| Installation records (`.manifest.json`) | Consumer project | gitignored in source repos |
| `integration.json` (active selection) | Consumer project | gitignored in source repos |
| Copilot agents, prompts, skills | `copilot-kit` | `copilot-kit` |
| Claude commands (future) | `claude-kit` | `claude-kit` |
| `ai-kit.manifest.json` | Each kit | Committed to kit repo |
| `project-tooling.json` | Consumer project | Consumer repo |
